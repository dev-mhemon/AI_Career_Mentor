## R18 draft acceptance detail

Follow **both** accepted C09 R18 clauses and C05 R18. Before navigation, sessionStorage contains exactly the required draft data `{channel, normalized_identifier, contact_masked, expires_at, context}`. Use the entered normalized email/+880 phone for verify/resend, masked contact only for display. This identifier is required draft state; do not remove it under a blanket “no PII in storage” assertion.

Expiry is **min(server challenge expiry, ten minutes)**; resend updates expiry from server. Navigate `/verify?channel=<channel>` with no contact identifier. Reload restores only an unexpired draft. Missing/expired state or a fresh tab asks for identifier re-entry; do not recover it from URL, telemetry or persistent localStorage. Clear on verified, expired or cancelled sign-out. Screen02 UNVERIFIED_ACCOUNT and settings secondary-contact flows create the same draft from entered normalized identifier. Passwords, verification codes, JWTs and refresh tokens never enter this draft. Apply no-identifier-URL behavior to reset-password later without implementing recovery here. Context is local draft state, not a new wire enum.
