- **D001 remains accepted:** fresh Supabase Auth and primary application PostgreSQL. The four historical TypeORM migrations remain archival in `backend/src/migrations`; their CLI data source throws before connecting. ORM has no entities/migrations, `synchronize=false`, `migrationsRun=false`. No old database/container/volume is removed or migrated.
- **ADR-020 implementation:** exact 21 forward, 21 down and eight test files copied from the reviewed export, with independent hash verification against both manifests. Down files are outside the forward directory. New boundary tests live separately. Future corrections require reviewed forward versions; startup refuses to overwrite a different existing migration checksum.
- **Data access:** retain TypeORM's transaction-capable DataSource/EntityManager as a PostgreSQL connection manager, without an ORM schema model. Application transactions explicitly `SET LOCAL ROLE service_role` and use a user advisory lock in a preceding READ COMMITTED statement. Status is rechecked in write transactions. Auth and app UUID are identical; backend roles come exclusively from `admin_users`. Auth bootstrap consults live Supabase user identities and confirmed contacts, never user metadata. No email matching/account merging is performed.
- **Toolchain deviation:** C02's pnpm/Jest examples do not match this source repository's npm lockfiles and existing Vitest suites. Retain npm (lockfile v3), Node >=24 (tested 24.19.0/npm 11.9.0), Vitest 5.0.3 and both existing frameworks. No dependency/lockfile upgrade is required. Supabase CLI **2.121.0** and PostgreSQL **17.11.0.004** are the locally tested integration versions; CI pins that CLI and Node version. This is an explicit compatibility decision, not evidence that the older document examples were executed.
- **API transition:** canonical prefix `/api/v1`, unversioned `/health`, standard success/error envelopes and `X-Request-Id`. The existing frontend still calls a transitional `POST /api/v1/auth/sync` for verified live-session bootstrap; this adapter is not counted as a C05 catalog endpoint. Canonical `GET /auth/me`, `POST /auth/oauth/session`, profile/preferences/settings/alias and goal read/confirmation are implemented. Legacy `/api/auth/*` URLs are retired. OTP/password/refresh/link/delete workflows and full UI are not claimed implemented.
- **Access:** JWT signature/expiry/issuer/audience/UUID first, DB status, DB admin role, global flag, override/default, ownership. Missing application mappings fail closed outside explicit bootstrap. `auth/me` and bootstrap preserve suspended state; all effective access becomes false. Future logout/deletion endpoints must explicitly carry the AZ-SUSP exception. Admin does not bypass resource ownership. No private chat/context admin endpoint exists. Existing-data read policies remain available under generation feature-off; technology-update reads still need access. Feature policy branches have executable tests but generation endpoint integration remains a later gate.
- **Progress:** no synthetic Junior level. Self-reported skills are stored as canonical IDs; unresolved aliases return candidates without AI calls. Explicit interpretations are scoped to the user, deduplicated with the profile update in one transaction, capped at 100. Only confirmed goal levels get progress rows. Stronger progress/evidence is preserved. Goal confirmation is serialized per user and capped at three active confirmed goals.
- **CI limits:** `database-ci.yml` is executable and locally checked with actionlint 1.7.7. GitHub Actions API access returned `Forbidden`; no remote run, artifact URL, release approval or acceptance is fabricated. Local raw evidence identifies the base commit plus worktree file hashes because implementation changes have not been committed/pushed.
