## Scoped Requirements & Decisions
1. **`SessionApprovalService` Session Revocation & Verification Helpers**:
   - `revokeSession(userId, sessionId, db?)`: Executes parameterized SQL:
     `UPDATE private.approved_auth_sessions SET revoked_at = clock_timestamp(), updated_at = clock_timestamp() WHERE user_id = $1::uuid AND session_id = $2::uuid AND revoked_at IS NULL`
     Returns `boolean` indicating if a session was revoked (idempotent, supports both injected `DatabaseService` and passed `EntityManager`).
   - `isSessionApproved(userId, sessionId, db?)`: Executes parameterized SQL:
     `SELECT 1 FROM private.approved_auth_sessions a JOIN public.users u ON u.id = a.user_id WHERE a.user_id = $1::uuid AND a.session_id = $2::uuid AND a.revoked_at IS NULL AND u.status = 'active' AND u.verified_contact = true LIMIT 1`
     Returns `boolean` confirming the session is active, unrevoked, and owner has verified contact.

3. **EP-A07 Canonical Logout (`POST /api/v1/auth/logout`)**:
   - Protected route guarded by `AccessGuard` requiring an active, verified, approved session.
   - Calls `SessionApprovalService.revokeSession(userId, sessionId)`.
   - Best-effort upstream GoTrue session invalidation via `POST /auth/v1/logout?scope=local` using bearer token; does not fail if upstream token is expired or network fails.
   - Returns C05 `200` with `LogoutDTOEnvelope` (`{ success: true, data: { logged_out: true } }`).
   - Guarantees immediate rejection of the bearer token by both `AccessGuard` (403 `UNVERIFIED_ACCOUNT`) and PostgREST RLS (`has_approved_session` returns `false`).

4. **EP-A06 Canonical Token Refresh (`POST /api/v1/auth/refresh`)**:
   - Public route (`@Policy({ public: true })`) taking `{ refresh_token }`.
   - DTO validation via `normalizeRefreshTokenRequest` requiring non-empty string.
   - Exchanges token with GoTrue via `POST /auth/v1/token?grant_type=refresh_token`.
   - Maps timeouts to 504 `PROVIDER_TIMEOUT`, 5xx to 502 `PROVIDER_ERROR`, and 400/401/422 to 401 `REFRESH_TOKEN_INVALID`.
   - Extracts `user.id` and `session_id` from newly issued access token.
   - Critical Security Gate: checks `SessionApprovalService.isSessionApproved(userId, sessionId)`. If unapproved or revoked, rejects immediately with 401 `REFRESH_TOKEN_INVALID` and never calls `approveSession`.
   - Executes foreground transaction updating `last_active_at` with R24 5-minute coalescing.
   - Returns flat C05 `200 AuthSessionDTO`.
