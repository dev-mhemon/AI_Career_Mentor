## Scoped Requirements & Decisions
1. **EP-A08 Canonical Forgot Password (`POST /api/v1/auth/forgot-password`)**:
   - Public route (`@Policy({ public: true })`) taking `ForgotPasswordRequestDTO` (`{ identifier }`).
   - Normalization via `normalizeForgotPasswordRequest`: trims and lowercases email, validates Bangladesh mobile or email, rejects invalid contact or unknown fields.
   - Enforces R31 abuse and rate-limit controls via `AuthAbuseControl.reserveSend(input, ip)` (`RESEND_COOLDOWN_ACTIVE` 429, `OTP_LIMIT_EXCEEDED` 429).
   - Fail-closed gate: fails with 503 `SERVICE_UNAVAILABLE` if abuse control, OTP store, or email provider transport is unconfigured.
   - Rejects phone identifier with 503 `SERVICE_UNAVAILABLE` pending phone/SMS provider implementation.
   - Anti-enumeration invariant: returns uniform C05 `202 Accepted` (`{ "success": true, "data": { "message": "If the account exists, a code was sent." } }`) for unknown accounts, unverified accounts, or suspended accounts without dispatching email.
   - For active, verified email accounts: dispatches domain-separated reset OTP via `EmailRegistrationProvider.sendPasswordResetChallenge`.

2. **EP-A09 Canonical Reset Password (`POST /api/v1/auth/reset-password`)**:
   - Public route (`@Policy({ public: true })`) taking `ResetPasswordRequestDTO` (`{ identifier, code, new_password, confirm_new_password }`).
   - Normalization via `normalizeResetPasswordRequest`: validates 6-digit code, configured minimum password length (`AUTH_PASSWORD_MIN_LENGTH`, default 8) up to 128 characters, nonnumeric requirement, and exact password confirmation match (`PASSWORD_MISMATCH` 422).
   - Rejects unknown user with 410 `VERIFICATION_CODE_EXPIRED` (anti-enumeration).
   - Prevents pre-OTP account enumeration of suspended users: status check is not executed before OTP verification. Instead, invalid OTP probes against suspended accounts fail challenge verification (422/410), while valid OTP triggers the locked transaction which verifies active status and returns 403 `ACCOUNT_SUSPENDED`.
   - Atomically verifies challenge and consumes OTP via `OtpSecretStore.verifyAndConsumeOtp` using `'reset_password'` purpose.
   - Durably synchronizes password update and session revocation inside a locked transaction `this.database.transaction(userId, ..., true)` holding `SELECT status FROM public.users WHERE id=$1 FOR UPDATE`. Revokes all sessions in PostgreSQL via `this.approvals.revokeAllUserSessions(userId, db)` and updates GoTrue password via Admin API: `PUT /auth/v1/admin/users/{userId}` (with bounded compensating `revokeAllUserSessions(userId)` retry if the transaction fails after `updateGoTrueUserPassword` succeeds). After `verifyAndConsumeOtp` completes and consumes the OTP, `resetPassword` executes `this.revokeGoTrueUserSessions(userId)` outside `verifyAndConsumeOtp` with transaction-scoped `SET LOCAL statement_timeout` and `SET LOCAL lock_timeout` so post-commit GoTrue cleanup failures cannot roll back local session revocations or abort OTP consumption.
   - Returns C05 `200 OK` (`{ "success": true, "data": { "password_reset": true } }`).

3. **CodeRabbit Review Findings Resolved**:
   - **Finding 1 (Anti-enumeration)**: Pre-OTP account enumeration of suspended users prevented. Suspended check moved inside OTP verification callback via locked transaction.
   - **Finding 2 (Configured password length)**: Read `AUTH_PASSWORD_MIN_LENGTH` in `resetPassword` and passed to `normalizeResetPasswordRequest(body, configuredMinimum)`.
   - **Finding 3 (Timing & 502 status oracle)**: Pre-flight `this.emailProvider.ready()` called before user query; `sendPasswordResetChallenge` dispatched asynchronously with `.catch(...)` error logging to guarantee uniform 202 status and constant time.
   - **Finding 4 (Atomic/durable session revocation)**: Password change and local session revocation serialized within `this.database.transaction(userId, ..., true)` holding row-level lock; revokes local sessions via transactional `db` runner (with bounded compensating retry if commit fails after `updateGoTrueUserPassword` resolves) and completes `verifyAndConsumeOtp` before running `revokeGoTrueUserSessions(userId)`.
   - **Finding 5 (Session validation in AccessGuard & GoTrue admin session invalidation)**: `AccessGuard` strictly requires `req.user.sessionId` and validates session approval status via `has_approved_session`. In `resetPassword`, `revokeGoTrueUserSessions` runs after `verifyAndConsumeOtp` (logging any post-commit OTP consumption failure) and executes each cleanup attempt inside a dedicated transaction that sets `SET LOCAL statement_timeout = <safeTimeoutMs>` and `SET LOCAL lock_timeout = <safeTimeoutMs>` before invalidating GoTrue refresh tokens (`UPDATE auth.refresh_tokens SET revoked = true, updated_at = clock_timestamp() WHERE user_id = $1::text AND COALESCE(revoked, false) = false`) and deleting upstream GoTrue sessions (`DELETE FROM auth.sessions WHERE user_id = $1::uuid`), awaiting full transaction rollback and query-runner release before returning and mapping SQLSTATE `57014`/`55P03` to non-retryable 504 `PROVIDER_TIMEOUT` and other errors to 502 `PROVIDER_ERROR`.
   - **Finding 6 (Replay error mapping)**: In `OtpSecretStore.verifyAndConsumeOtp`, `ALREADY_VERIFIED` is mapped to `410 VERIFICATION_CODE_EXPIRED` for `reset_password` purpose, preventing 409 leakage on replayed challenges.

4. **R31/S1 Domain Separation**:
   - Complete domain separation between signup verification (`verify_email`) and password recovery (`reset_password`):
     - Redis challenge key: `auth:v1:challenge:reset_password:{contactKey}` vs `auth:v1:challenge:{contactKey}`
     - Redis secret key: `auth:v1:otp:secret:reset_password:{userId}` vs `auth:v1:otp:secret:{userId}`
     - HMAC digest domain prefix: `auth:v1:otp:reset_password:...` vs `auth:v1:otp:...`
   - A code issued for signup verification is immediately rejected if submitted to `reset-password` (fails closed 410/422), and vice versa.

5. **Session Revocation Helper (`revokeAllUserSessions`)**:
   - Added `revokeAllUserSessions(userId: string, db?: EntityManager): Promise<number>` to `SessionApprovalService`.
   - Parameterized SQL updates all unrevoked sessions for `userId`, returning affected count.
