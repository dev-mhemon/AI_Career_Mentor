  - **Durable PostgreSQL Job Producer, Consumer & Reaper (`R12`, `R13`, `ADR-017`):**
    - `JobProducerService`: validates `v: 1` envelopes (`args` + `expected_refs` across all 6 async `job_kind`s, rejecting sync-only `career_goal`, forbidden prompt/secret keys, and `> 32,768` UTF-8 byte payloads), inserts queued `public.ai_requests` rows atomically (participating in caller `tx` or opening a `DatabaseService` transaction), and maps Postgres `23505` on `uq_ai_requests_idempotency` to `409 IDEMPOTENCY_KEY_REUSED`.
    - `PostgresJobQueueConsumer`: claims batches via `FOR UPDATE SKIP LOCKED` on `idx_ai_requests_queue` and commits `queued -> preparing` BEFORE invoking any external handler/provider; runs a 30s fenced heartbeat (`(id, locked_by, attempt_count)`) that aborts `AbortSignal` on fence loss; re-locks `public.ai_requests FOR UPDATE` inside an atomic commit gate verifying fence, 120s lease freshness, 1h age deadline, active owner & `private.effective_feature_access`, and `verifyExpectedRefs` (`STALE_JOB_INPUT`), then commits domain artifact + `public.ai_generations` + `status = 'succeeded'` + `input_payload = NULL` in one transaction; clears `input_payload = NULL` on terminal failure and uses strict two-step `preparing -> failed` then separate `failed -> queued` with bounded exponential backoff for retries.
    - `JobReaperService`: sweeps stalled `'preparing'` jobs (`FOR UPDATE SKIP LOCKED`), strictly executes two-step `preparing -> failed` then separate `failed -> queued` (never `preparing -> queued`, preserving `private.validate_ai_request_status()` SQLSTATE `23514`), marks exhausted/expired jobs terminal (`retryable = false`, `input_payload = NULL`), and samples `randomFn()` once per `computeRetryBackoffSeconds` calculation.
  - **Internal AI Gateway (`AiModule`, zero HTTP controllers, `ADR-008`, `C08` §4–5, `C05` §15.12, `R26`):**
    - `AiGatewayService`: sole internal egress boundary across all 9 `public.ai_task` workflows; validates `AIRequestDTO`, enforces `QuotaGuardService` 24h quotas and `R26` bounds (`1..10000`, `<= 5s` TTL, safe defaults), resolves SHA-256-verified prompts via `PromptManagerService` (`timingSafeEqual`, fail-closed `502 AI_SERVICE_ERROR`), builds PII-redacted / `<untrusted_data>` XML-delimited context envelopes via `ContextBuilderService`, routes active task-approved models (`real_user_data_approved = true` fail-closed in `real_user` mode) via `ModelRouterService` (`isAvailable()` read-only filter), enforces per-model `CircuitBreakerService` (`5` consecutive 5xx/timeout failures in `60s` -> `60s` `OPEN` quarantine -> single `HALF_OPEN` canary guarded by unique `canaryToken` ownership in `acquireAttempt()`/`releaseCanary()`/`recordSuccess()`/`recordFailure()` so late pre-open releases or `rate_limit`/aborted probes never deadlock or clobber active canaries), validates outputs strictly via `OutputValidatorService` (including roadmap DAG acyclicity and "Job Ready" claim rejection), and records content-free `public.ai_generations` telemetry (`output_hash` only, nullable `request_id` validated to trimmed UUID or `null` on both passed and failed validation paths).
    - `SyntheticProviderAdapter`: deterministic offline `ProviderAdapter` supporting all 9 tasks and programmable fault/timeout/rate-limit/invalid-schema modes with zero live API keys.
  - **Frontend Typed Job Polling & Component 28 `AILoadingState` (`C09` §2.7, `C05` §13.6/§14.13/§16.4–5):**
    - `frontend/src/lib/api/client.ts` & `error-mapper.ts`: typed `JobAcceptedDTO`, `JobStatusDTO`, `getJobStatus`, `withIdempotencyKey`, and curated user-facing `AI_AND_JOB_SAFE_ERRORS` messages leaking zero provider/model internals.
    - `frontend/src/components/ui/ai-loading-state.tsx`: non-blocking `inline_banner` and `full_section_skeleton` variants polling `EP-J01` at `retry_after_seconds`, setting `aria-busy="true"` while active, respecting `prefers-reduced-motion`, aborting client polling cleanly on unmount without cancelling server execution, and displaying preserved-data reassurance + Retry action on failure.
