  - **`CareerGoalService` Business Rules, Concurrency & Synchronous AI Goal Interpretation (`C08` §6.2.1 / §7.2, `R07`, `R24`, `R29`):**
    - `EP-C01` (`POST /api/v1/career/goals`, `201 Created`): Validates `goal_text` (`3..300` trimmed Unicode code points via `Array.from(value).length` matching PostgreSQL `char_length(...)`, rejecting NUL bytes and unpaired UTF-16 surrogates); pre-checks `private.effective_feature_access(user_id, 'roadmap_generator')` and active goal/roadmap count `< 3` (`409 ROADMAP_LIMIT_REACHED`); executes `AiGatewayService.execute` (`task: 'goal_interpretation'`, `timeout_ms: 9_500` with shared `AbortController` deadline signal, `untrusted_inputs: [goal_text]`) strictly OUTSIDE any DB transaction; rejects non-technology goals with `422 OUT_OF_SCOPE_GOAL`; resolves roles strictly against commit-time `public.career_roles` (`status = 'approved' AND deleted_at IS NULL`, failing closed with `502 AI_VALIDATION_FAILED` if empty); clears `proposed_role` and `alternative_roles` when `status === 'clarifying'`; and commits in ONE DB transaction (`public.users FOR UPDATE` first, write-boundary recheck of `effective_feature_access` and `< 3` active count, `R24` `foreground = true`).
    - `EP-C02` (`GET /api/v1/career/goals`, `200 OK`, `Gate: none`): Enforces `WHERE g.user_id = $1`, optional `status` filter (`422 INVALID_ENUM_VALUE` on invalid enum), deterministic cursor pagination (`ORDER BY g.created_at DESC, g.id DESC`) selecting `g.created_at::text AS created_at_cursor` to preserve PostgreSQL microsecond precision in `PageMetaDTO.next_cursor`, single-query batching of distinct `alternative_role_ids` across page rows (preventing N+1 role queries), and `R24` `foreground = false`.
    - `EP-C03` (`GET /api/v1/career/goals/:id`, `200 OK`, `Gate: none`): Validates `:id` UUID (`400 INVALID_FORMAT`), enforces `WHERE g.user_id = $1 AND g.id = $2` (`404 RESOURCE_NOT_FOUND` on missing or foreign ID), serializes complete `R29` `RoleOptionDTO` (nullable `rationale`), and sets `R24` `foreground = false`.
    - `EP-C04` (`POST /api/v1/career/goals/:id/clarifications`, `200 OK`): Validates `answer` (`1..300` trimmed Unicode code points via `Array.from(value).length`, rejecting NUL/unpaired surrogates); pre-checks owner, `status === 'clarifying'` (`409 INVALID_STATE_TRANSITION`), and `clarification_round < 2` (`409 CLARIFICATION_LIMIT_REACHED`); invokes `AiGatewayService.execute` OUTSIDE any DB transaction with a shared `9.5s` `AbortController` + `Promise.race` deadline (`504 AI_TIMEOUT` on stalled gateway); re-locks `public.users` then `public.career_goals FOR UPDATE` in ONE transaction, rechecks `effective_feature_access`, status, round `< 2`, and concurrent revision invariance (`goal_text`, `clarification_round`, `clarification_question`, `proposed_role_id`, `alternative_role_ids`, `suggested_level`, `updated_at`), advances `updated_at = GREATEST(clock_timestamp(), updated_at + interval '1 microsecond')`, increments `clarification_round`, and coerces to `awaiting_confirmation` on round 2 using only matched approved catalog roles (failing closed with retryable `502 AI_VALIDATION_FAILED` if no approved role matches).
    - `EP-C05` (`POST /api/v1/career/goals/:id/confirm`, `200 OK`): Executes in ONE DB transaction locking `public.users FOR UPDATE` then `public.career_goals FOR UPDATE`; rechecks `private.effective_feature_access`; verifies confirmable status (`409 GOAL_ALREADY_CONFIRMED` if already confirmed, `409 INVALID_STATE_TRANSITION` otherwise); validates `target_level` (`422 INVALID_ENUM_VALUE`) and verifies `canonical_role_id` is in `{proposed_role_id} ∪ alternative_role_ids` and approved in `public.career_roles` (`422 ROLE_MISMATCH`); enforces `< 3` active goals/roadmaps (`409 ROADMAP_LIMIT_REACHED`); updates goal to `confirmed` (`confirmed_at = clock_timestamp()`), excludes the confirmed role from `alternative_roles` in the response DTO, and atomically calls `ProfileService.initializeProgress(db, userId)` inside the SAME transaction per `R07`.
    - `EP-C06` (`PATCH /api/v1/career/goals/:id`, `200 OK`): Validates updated `goal_text` (`3..300` trimmed Unicode code points); rejects `confirmed` with `409 GOAL_ALREADY_CONFIRMED` and `discontinued` with `409 INVALID_STATE_TRANSITION`; re-interprets via `AiGatewayService.execute` OUTSIDE any DB transaction (`422 OUT_OF_SCOPE_GOAL` on non-tech); re-locks `public.users` + `public.career_goals FOR UPDATE` in ONE transaction, rechecks status, `effective_feature_access`, and concurrent revision invariance (`status`, `clarification_round`, `goal_text`, `clarification_question`, `proposed_role_id`, `alternative_role_ids`, `suggested_level`, `updated_at`), advances `updated_at = GREATEST(clock_timestamp(), updated_at + interval '1 microsecond')`, resets clarification rounds (`0` when `awaiting_confirmation`, `1` when `clarifying`), and persists updated interpretation against commit-time approved roles.
    - `EP-C07` (`DELETE /api/v1/career/goals/:id`, `200 OK`, `Gate: none`): Executes in ONE DB transaction locking `public.users FOR UPDATE` then `public.career_goals FOR UPDATE` (`404 RESOURCE_NOT_FOUND` on missing/foreign, `409 INVALID_STATE_TRANSITION` if already discontinued); sets `status = 'discontinued', discontinued_at = clock_timestamp()`; if a linked `public.roadmaps` row exists, archives it (`status = 'archived'`, `is_focus = false`) FIRST so `uq_roadmaps_one_focus` is never violated, and if it was Focus, deterministically promotes another active `locked` roadmap for that user to `is_focus = true` (or `null` if none); preserves all `learning_evidence`, `skill_progress`, `achievement_history`, and `daily_plans` rows.
