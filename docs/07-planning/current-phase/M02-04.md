  - Deliverable 2 — Canonical Single-Refresh-Per-401 Retry Helper (`EP-A07`):
    - `frontend/src/lib/auth/actions.ts`: Implemented and exported JSDoc-documented `withSingleSessionRefresh` wrapping authenticated backend API calls (`linkIdentityAction`, `addContactAction`, `updateLearningSettingsAction`, and `saveProfileSetupAction`). On HTTP `401` (`UnauthorizedError`), coalesces concurrent requests sharing the same refresh token via an in-flight Promise map (`coalesceRefreshSession`), attempts at most one token refresh via `refreshSession(session.refresh_token)` (`EP-A07`), persists rotated tokens via `supabase.auth.setSession`, and retries once; on a refresh failure, an invalid refresh response, or a `setSession` error/throw, skips `safeSignOut` if `session.refresh_token` was already rotated concurrently (otherwise calling `safeSignOut(supabase)`); on a missing `refresh_token` or a repeated `401` after retry, always invokes `safeSignOut(supabase)`, and every failure path redirects to `/login` with zero infinite retry loops.
  - Deliverable 3 — Screen 22 (`/settings`) Learning Settings Form (`EP-P04`):
    - `frontend/src/lib/profile/actions.ts`: Implemented `updateLearningSettingsAction` with strict validation for `timezone` (non-empty valid IANA timezone) and `preferred_daily_hours` (`0.5` to `12.0` in `0.5` increments; rejects `NaN`/`Infinity`/out-of-range/non-`0.5`-multiples), wrapped in `withSingleSessionRefresh`; `loadProfileForSetup` uses a read-only client (`createSupabaseServerClient({ readOnly: true })`) and returns `{ profile: null, unauthorized: true }` without token rotation during SSR.
    - `frontend/src/components/settings/learning-settings-form.tsx`: Created SSR-safe client component for Screen 22 learning settings (`EP-P04`) with accessible labels, field error alerts, localized status banner, suspended-account notice, and interactive browser timezone auto-detection.
