# M03-03 — Privacy Retention Cutoffs, Physical Purge Worker, Bounded Provider Cleanup Outbox & Account Deletion UI/Integration

Task / goal / observable acceptance:
- Implement Phase 1 Slice `M03-03` (`Privacy Retention Cutoffs, Physical Purge Worker, Bounded Provider Cleanup Outbox & Account Deletion UI/Integration`) per `docs/07-planning/master-execution-plan.md` §4 and §5:
  - Deliverable 1 — Bounded Provider Cleanup Outbox Processing (`backend/src/account/services/provider-cleanup.service.ts`):
    - Encrypts and decrypts provider object references using AEAD `aes-256-gcm` with authenticated additional data (`AAD = request_id:provider_key`) to prevent reference swapping and tampering (`R35`).
    - Validates outbox entry schema strictly (`provider_key`, `encrypted_object_ref`, `attempts` <= 5, `next_retry_at`, `state: 'pending'`), rejecting unknown fields, plaintext references, or credentials.
    - Fails closed on missing or insecure key configuration outside `test` and `development` environments (`nodeEnv !== 'test' && nodeEnv !== 'development'`).
    - Implements bounded outbox batch processing (`processOutboxBatch`) with 30-day deadline expiry scrubbing (`provider_cleanup_expires_at`), 10-second per-entry timeout, finite retries (max 5) with exponential backoff (`2^attempts * 60s`, capped at 24h), and sets `provider_deletion_requested = true` once all entries succeed.
  - Deliverable 2 — Privacy Retention Cutoffs & Physical Purge Worker (`backend/src/account/services/privacy-retention.service.ts`):
    - Enforces canonical retention windows: raw quiz answers and mentor text clamped to 1..90 days (default 90 days, `R08`), and AI operational request logs clamped to 1..30 days (default 30 days, `R09`).
    - Evaluates dual-predicate raw text expiration (`isRawTextExpired` helper: earlier of explicit `expires_at` and `created_at + 90 days`).
    - Executes physical purge operations (`purgeExpiredData`): redacts `quiz_answers.answer_text` to NULL past 90 days while preserving answer records, deletes expired `messages`, deletes `ai_requests` past 30 days, deletes expired `ai_context_records`, and scrubs expired `provider_cleanup` outbox payloads.
    - Measures physical purge lag and logs a `PURGE_LAG_ALERT` warning if purge lag exceeds the 24-hour SLA threshold.
  - Deliverable 3 — Account Deletion Outbox & Purge Integration (`backend/src/account/services/account-deletion.service.ts` & `AccountModule`):
    - During deletion execution (`requestDeletion`), queries linked identity providers in `public.user_auth_providers` before deleting the user row, encrypts outbox entries via `buildOutboxEntries`, and updates `provider_cleanup` and `provider_cleanup_expires_at` (30 days from deletion) in `public.account_deletion_requests`.
    - Exposes `processProviderCleanupOutbox` and `executePrivacyRetentionPurge` delegation methods.
    - Registers and exports `ProviderCleanupService` and `PrivacyRetentionService` in `AccountModule`.
  - Deliverable 4 — Frontend API Client & Server Actions (`frontend/src/lib/api/client.ts` & `frontend/src/lib/auth/actions.ts`):
    - Implements `requestAccountDeletion` (`EP-X01`) and `getAccountDeletionStatus` (`EP-X02`) with dual `Bearer` JWT and `Authorization: DeletionReceipt <token>` header support.
    - Implements `requestAccountDeletionAction` requiring literal `confirmation === 'DELETE'`, live password or OAuth `reauth_token`, and clearing local session state on completion.
    - Implements `pollAccountDeletionStatusAction` polling `EP-X02` using the signed `DeletionReceipt`.
  - Deliverable 5 — Screen 22 Danger Zone Account Deletion UI (`frontend/src/components/settings/account-deletion-card.tsx` & `frontend/src/app/settings/page.tsx`):
    - Implements Screen 22 (`/settings`) Danger Zone card and confirmation modal with accessible ARIA dialog attributes, literal "DELETE" input validation, password / OAuth re-authentication tabs, and `DeletionReceipt` status polling.
    - Strictly follows Simple React State Rule (derived polling state, `useRef` guards for navigation, and `try / catch` around storage clearing) and R18 privacy rules (zero tokens or PII in URLs or logs).
    - Preserves `AZ-SUSP` access, rendering the deletion card for suspended users while disabling non-deletion settings forms.
  - Deliverable 6 — Deterministic Unit & Synthetic Integration Tests:
    - Expanded test coverage across backend (`provider-cleanup.service.spec.ts` 25 tests, `privacy-retention.service.spec.ts` 9 tests, `account-deletion.spec.ts` 44 tests) and frontend (`client.test.ts` 27 tests, `actions.test.ts` 86 tests, `account-deletion-card.test.tsx` 10 tests, `page.test.tsx` 12 tests) with zero-parser parameter-based mocks.
