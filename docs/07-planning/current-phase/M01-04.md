## Scoped Requirements & Decisions
1. **Candidate S1 Redis OTP Secret Store**:
   - 6-digit numeric CSPRNG OTP generation.
   - HMAC-SHA256 digest with domain separation `auth:v1:otp:${userId}:${normalizedEmail}:${code}` using `AUTH_OTP_HMAC_SECRET` (validated >= 32 bytes).
   - In `storeOtp`, `this.abuse.issueChallenge` is called first to obtain effective `challenge.expiresInSeconds` (min of validity and `AUTH_OTP_TTL_SECONDS`), saving secret under `auth:v1:otp:secret:${userId}` with `challenge.expiresInSeconds` so secret never outlives challenge, returning `{ expiresInSeconds }`.
   - Verification using `crypto.timingSafeEqual` against stored digest in Redis.
   - Abuse control / rate limiting via Redis Lua `challengeScript` (R31 5 attempts max; atomic consume on match; delete/invalidate secret when attempts exhausted or consumed; atomic abort phase clearing busy reservation on verify callback exception without counting against failure quota).
   - Fail closed with retryable 503 `SERVICE_UNAVAILABLE` on Redis outage.
   - Registered `AUTH_OTP_HMAC_SECRET` in config validation, `backend/.env.example`, and canonical `docs/00-governance/config-register.md`.
2. **Option 2B `EmailRegistrationProvider` Activation (`EP-A01` & `EP-A04`)**:
   - `ready()` requires both configured environment (`AUTH_OTP_HMAC_SECRET`, `SUPABASE_SERVICE_ROLE_KEY`, `AUTH_REDIS_URL`), injected `this.otpStore`, AND configured `this.transport`; fails closed with 503 if any are missing.
   - `findByEmail()` queries `auth.users` and `public.users`, returning `verified: Boolean(row.verified_contact)` so unverified public accounts allow resend even if GoTrue `email_confirmed_at` was set (Failure Boundary 2 recovery).
   - `createPending()` calls GoTrue Admin API `createUser({ email_confirm: false })`, mapping 422 `email_exists` to 409 `CONTACT_ALREADY_REGISTERED`.
   - `sendChallenge()` fails closed with 503 if transport or otpStore missing, generates 6-digit OTP, stores in S1 Redis store obtaining effective `expiresInSeconds`, delivers via `await this.transport(identity.email, otp, signal)`, and returns `{ expiresInSeconds }`.
3. **EP-A02 (`POST /api/v1/auth/verify-email`)**:
   - Step 1: Validates DTO (`email`, 6-digit `code`). Queries canonical application user `public.users` joined with `public.user_auth_providers (provider = 'email')`. If no user exists, returns 410 `VERIFICATION_CODE_EXPIRED` before OTP consumption. If `verified_contact === true` or `verified_at !== null`, returns 409 `ALREADY_VERIFIED` before OTP consumption (no `auth.users` fallback). Verifies & atomically consumes OTP via `OtpSecretStore` + R31.
   - Step 2: Confirms GoTrue user via Admin API `PUT /auth/v1/admin/users/{id}` (`{ email_confirm: true }`), idempotent on already-confirmed, maps timeout to 504 `PROVIDER_TIMEOUT` and upstream error to 502 `PROVIDER_ERROR`.
   - Step 3: In serialized TypeORM transaction on `userId`:
     - Updates `public.users` (`verified_contact = true`, `last_login_at = now()`, `last_active_at = now()`, `updated_at = now()`).
     - Updates `public.user_auth_providers` (`verified_at = now()`, `updated_at = now()`).
     - Guard: requires `rowCount === 1` on BOTH updates. If either affects 0 rows, rolls back immediately before default row inserts and returns 409 `ALREADY_VERIFIED`.
     - Inserts default `public.user_profiles` and `public.user_preferences` rows (`ON CONFLICT (user_id) DO NOTHING`).
   - Step 4: Mints and exchanges magiclink session for confirmed user, validates returned `user.id` and `session_id`, approves `(user_id, session_id)` with `'email_verification'` via `SessionApprovalService`, and returns flat C05 200 `AuthSessionDTO`.
