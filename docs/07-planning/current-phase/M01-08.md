## 2. Implemented Changes

1. **Access Policy & Guard (`backend/src/auth/policy.ts`, `backend/src/auth/guards/access.guard.ts`):**
   - Added `allowUnverifiedContact?: boolean` to `AccessPolicy` and JSDoc comments on `Policy` and `AccessGuard.canActivate`.
   - Updated `AccessGuard.canActivate` with scoped exemption `unverifiedContactExempt = Boolean(p.allowUnverifiedContact) && !u.verified_contact`, allowing active users (`u.status === 'active'`) with unverified contacts (`verified_contact = false`) to access `EP-A12` while strictly enforcing session approval (`approved === true`) on verified accounts and rejecting suspended users (`403 ACCOUNT_SUSPENDED`).

2. **DTO Normalization (`backend/src/auth/registration.dto.ts`):**
   - Added `LinkIdentityRequestDTO` (`{ provider: 'google' | 'facebook' }`) and `normalizeLinkIdentityRequest(value: unknown)`, rejecting unsupported providers with `422 VALIDATION_FAILED` (`details[].code = 'INVALID_ENUM_VALUE'`).
   - Added `AddContactRequestDTO` (`{ channel: 'email' | 'phone'; contact: string }`) and `normalizeAddContactRequest(value: unknown)`, delegating to `normalizeContact` to validate email or Bangladesh mobile numbers (`422 INVALID_PHONE_NUMBER` / `422 VALIDATION_FAILED`).

3. **Backend Endpoints & Service (`backend/src/auth/controllers/auth.controller.ts`, `backend/src/auth/services/auth.service.ts`):**
   - Added `POST /api/v1/auth/identities/link` (`@HttpCode(200)`, `AZ-USER`) delegating to `AuthService.linkIdentity`.
   - `AuthService.linkIdentity`:
     - Fetches live Supabase Auth user (`GET /auth/v1/user`), verifies identity subject matches JWT `sub`, and confirms requested OAuth provider (`google` | `facebook`) is attached to `user.identities` (`422 PROVIDER_MISMATCH` if missing).
     - Within a locked user transaction (`this.database.transaction(identity.sub, ..., true, true)`):
       - Verifies `account.verified_contact === true` (`403 VERIFIED_CONTACT_REQUIRED` if false).
       - Checks `public.user_auth_providers` for conflicting `(provider, provider_subject)` owned by another `user_id` (`409 IDENTITY_LINK_CONFLICT`, including `23505` unique-constraint race handling).
       - Upserts `public.user_auth_providers` (`is_primary = false`) and returns unwrapped `{ linked_providers: string[] }`.
   - Added `POST /api/v1/auth/contact` (`@HttpCode(202)`, `@Policy({ allowUnverifiedContact: true })`) delegating to `AuthService.addContact`.
   - `AuthService.addContact`:
     - Normalizes channel and contact; fails closed with `503 SERVICE_UNAVAILABLE` for `'phone'` while the SMS gateway is disabled.
     - Verifies live Auth user identity and enforces R31 `AuthAbuseControl.reserveSend({ channel: 'email', identifier: email }, ip)`.
     - Within a locked user transaction (`this.database.transaction(identity.sub, ..., true, true)`):
       - Acquires transaction-scoped advisory lock `pg_advisory_xact_lock(hashtextextended('auth:pending-email:' || email, 1))`.
       - Checks `public.users.verified_contact` for `identity.sub`; if already `true`, immediately fails with `409 ALREADY_VERIFIED` to prevent corrupting account state.
       - Rejects with `409 CONTACT_ALREADY_REGISTERED` if the email belongs to another user (`public.users` or `public.user_auth_providers`) or if the current user already has a verified email provider row (`verified_at IS NOT NULL`).
       - Upserts unverified `'email'` provider row (`verified_at = NULL`).
     - Dispatches 6-digit OTP via `EmailRegistrationProvider.sendChallenge` and returns unwrapped `RegistrationPendingDTO` (`202 Accepted`).
   - `AuthService.verifyEmail`:
     - Pre-commit GoTrue synchronization: calls `confirmGoTrueUser(userId, !user.email ? email : undefined)`, passing `{ email, email_confirm: true }` when verifying an added contact without a prior email so GoTrue has the address before session minting via magiclink.

4. **Frontend API Client, Server Actions & Callback Route (`frontend/src/lib/api/client.ts`, `frontend/src/lib/auth/actions.ts`, `frontend/src/app/auth/callback/route.ts`):**
   - Added `LinkIdentityBody`, `LinkIdentityResponse`, `linkSocialIdentity`, `AddContactBody`, and `addContact` in `frontend/src/lib/api/client.ts` with JSDoc comments.
   - Added `linkIdentityAction` in `frontend/src/lib/auth/actions.ts`:
     - If the provider identity is already attached in Supabase, directly calls `linkSocialIdentity(session.access_token, provider)`.
     - Otherwise initiates Supabase OAuth identity linking (`supabase.auth.linkIdentity({ provider, options: { redirectTo: ...?flow=link&provider=... } })`) and redirects to OAuth provider URL.
   - Updated `frontend/src/app/auth/callback/route.ts` to handle `flow === 'link'`: exchanges code for updated session, confirms matching identity, calls `linkSocialIdentity(session.access_token, provider)`, and redirects to `/dashboard?linked=${provider}`. On exchange error, missing session, or unlinked identity during `flow === 'link'`, local session is preserved without `signOut` and redirected to `/dashboard?error=link_failed`.
   - Enabled `enable_manual_linking = true` in `supabase/config.toml` under `[auth]` to permit `supabase.auth.linkIdentity` calls.
   - Added `addContactAction` in `frontend/src/lib/auth/actions.ts`, persisting `mentor_verification_context` cookie and redirecting to `/verify?type=${channel}`.

## 5. Production & Hosted Supabase Deployment Checklist

For deployers configuring hosted Supabase environments:
- Enable 'Manual Linking' in the hosted Supabase project's Auth settings to permit `supabase.auth.linkIdentity`.
  - In Supabase Dashboard: Navigate to **Authentication -> Configuration -> Users & Security**, and toggle on **Allow manual linking** (`enable_manual_linking = true`).
  - Or via Management API: Ensure the project Auth config has `enable_manual_linking: true` matching `supabase/config.toml`.
