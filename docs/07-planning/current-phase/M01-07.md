## 2. Implemented Changes

1. **DTO Normalization (`backend/src/auth/registration.dto.ts`):**
   - Added `VerifyPhoneRequestDTO` (`{ phone: string; code: string }`) and `normalizeVerifyPhoneRequest(value: unknown)`.
   - Normalizes local (`01[3-9]\d{8}`) and E.164 (`+8801[3-9]\d{8}`) Bangladesh mobile numbers via `normalizeContact('phone', input.phone, 'phone')`, throwing `422 INVALID_PHONE_NUMBER` on invalid numbers and `422 VALIDATION_FAILED` on non-6-digit codes or extra fields.

2. **S1 OTP Domain Separation (`backend/src/auth/services/otp-secret-store.service.ts`):**
   - Extended `OtpPurpose` to `'verify_email' | 'verify_phone' | 'reset_password'`.
   - Enforced domain-separated HMAC digest (`auth:v1:otp:verify_phone:${userId}:${normalizedContact}:${code}`), Redis challenge key (`auth:v1:challenge:verify_phone:${contactKey}` with `{ channel: 'phone', identifier: normalizedContact }`), and Redis secret key (`auth:v1:otp:secret:verify_phone:${userId}`).

3. **Backend Endpoint & Service (`backend/src/auth/controllers/auth.controller.ts`, `backend/src/auth/services/auth.service.ts`):**
   - Added `POST /api/v1/auth/verify-phone` (`@HttpCode(200)`, `@Policy({ public: true })`, `AZ-PUB`) delegating to `AuthService.verifyPhone`.
   - `AuthService.verifyPhone`:
     - Looks up user and `'phone'` provider row (`public.users` + `public.user_auth_providers`); returns `410 VERIFICATION_CODE_EXPIRED` if absent and `409 ALREADY_VERIFIED` if already verified.
     - Verifies and consumes the `'verify_phone'` OTP via `OtpSecretStore.verifyAndConsumeOtp`:
       - Confirms GoTrue user phone and provisions deterministic ephemeral synthetic email `phone-${userId}@synthetic.mentor` (`PUT /auth/v1/admin/users/${userId}` with `{ phone_confirm: true, email: synthEmail, email_confirm: true }`, treating `422 already confirmed` idempotently, mapping timeouts to `504 PROVIDER_TIMEOUT` and upstream errors to `502 PROVIDER_ERROR`).
       - Atomically promotes `public.users` (`verified_contact = true`, `phone`), `public.user_auth_providers` (`verified_at = now()`), and provisions `public.user_profiles` and `public.user_preferences` with 0-row update conflict protection (`409 ALREADY_VERIFIED`).
     - Handles post-commit Redis consumption errors gracefully (`let committed = false` + `this.logger.error`).
     - Mints and approves the GoTrue session via `mintAndApproveSession(userId, phone, 'phone')` using `generate_link` + `/auth/v1/verify` with `synthEmail`, cleans up the ephemeral email and email identity from `auth.users` and `auth.identities`, and returns unwrapped `AuthSessionDTO` for single wrapping by `EnvelopeInterceptor`.

4. **Frontend API Client & Server Action (`frontend/src/lib/api/client.ts`, `frontend/src/lib/auth/actions.ts`):**
   - Added `VerifyPhoneBody` and `verifyPhone` (`POST /auth/verify-phone`) in `frontend/src/lib/api/client.ts`.
   - Wired `verifyOtpAction` in `frontend/src/lib/auth/actions.ts` to call `verifyPhone` when `type === 'phone'`, establish the Supabase session cookie, clear `mentor_verification_context`, and redirect based on `session.next_step`.
