# Shared project guidance — Codex and Antigravity

Start at [START-HERE](docs/00-governance/START-HERE.md), then use the [source register](docs/00-governance/source-of-truth.md), [context map](docs/00-governance/context-map.md) and [shared workflow](docs/00-governance/agent-workflow.md). The current task and handoff are linked from START-HERE; do not depend on earlier chat history.

- Explicit owner instructions define scope. The repository contains a merged Phase 1 foundation, not the complete MVP. Historical alignment instructions are not fresh permission to implement, push or deploy.
- Confirm the actual execution shell, root, branch, full HEAD and staged/unstaged/untracked status. Prefer explicitly selected Git Bash for agent terminal commands on Windows; the native PowerShell service workflow remains in the [runbook](docs/09-operations/runbook.md).
- For an authorized writing task on a clean checkout, use a dedicated task branch from the observed base. Preserve unrelated changes; use existing isolated checkouts and create a worktree only when requested or needed to protect other work. Sequential handoffs are the default; concurrent writers require separate branches/worktrees and non-overlapping ownership.
- Read applicable scoped instructions and relevant adopted sections before changes; expand context for dependencies. C01 owns product scope, C02 architecture, C03 domain meaning, C05 HTTP/DTOs, C06 exact SQL, C04 procedures, C08 AI and C09 UX. Record mismatches; existing code does not silently override a requirement.
- Preserve every byte in planning/reviewed-baseline/, the nine adopted core documents, adopted supabase/migrations/, supabase/rollbacks/ and the original eight supabase/tests/database/ suites. Never weaken their verifier or update hashes to hide a mismatch. Applied SQL corrections need a separately reviewed forward migration.
- Supabase supplies Auth AND primary PostgreSQL storage (D001). Do not replay legacy TypeORM migrations. Retain the transactional TypeORM connection manager with synchronize=false and migrationsRun=false.
- Keep strict TypeScript, established framework conventions, Node >=24, npm lockfiles and Vitest. Use the runbook for authorized installation/services; run verification appropriate to the change. Documentation-only work uses baseline/alignment/link/diff checks, not installation or the full application suite.
- Preserve OAuth next_step, nullable RoleOptionDTO rationale, explicit beginner None, stronger evidence, tenant isolation, suspension exceptions and existing-data reads under generation-off.
- Never log/commit credentials, private signing keys, JWTs, raw private practice/chat content or process environments. Document configuration from public templates and consumers. Only configured approved providers may receive real user data. Ignore files are not a security boundary.
- Avoid speculative modules, future routes and empty placeholders. Preserve frontend scoped guidance. Shared repository rules are portable; agent skills/settings and automatic rule discovery are not assumed portable or loaded.
- No force push, merge, deployment, shared DB reset or volume deletion. Use a destructive harness only when separately authorized with positively identified disposable-project safeguards. Commit, push and PR actions require task authorization; use focused Conventional Commits when authorized.

Maintain one current task record under docs/07-planning/current-phase/ using the workflow's compact template. Record branch/base/HEAD, source sections, changed files, decisions, commands/exit codes, tested source/worktree identity, artifacts, failures, blockers and the next action. Distinguish SPECIFIED, IMPLEMENTED, EXECUTED and ACCEPTED; owner sign-off is separate.
